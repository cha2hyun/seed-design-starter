# 프로젝트 구조 점검 및 개선 기록

점검일: 2026-09-09

Vite + React + TypeScript와 FSD 계층 구성이 일관되어 있고, SEED 토큰·번역·계층 경계를
자동으로 검사하고 있습니다. 기존 전체 검증과 테스트 98개가 통과한 상태에서, 추가 테스트로
드러난 동작 오류와 책임이 섞인 부분을 중심으로 개선했습니다.

## 구조와 책임

| 위치                       | 책임                                                          |
| -------------------------- | ------------------------------------------------------------- |
| `src/app`                  | 진입점, 공통 공급자, 라우터, 로그인 가드, 스타일 설정         |
| `src/pages`                | 홈, 상품 상세·등록, 로그인, 프로필, 설정, 대시보드, 단계별 폼 |
| `src/widgets`              | 헤더, 사이드바, 푸터, 상품 목록 등 조합된 화면 블록           |
| `src/features`             | 상품 등록·필터, 계정 메뉴, 언어·테마 선택 등 사용자 행동      |
| `src/entities`             | 상품·세션 타입, 저장소, 쿼리와 관련 UI                        |
| `src/shared`               | 공통 통신, 설정, 유틸리티, UI, 한국어·영어 번역, SEED 스니펫  |
| `config`, `scripts`, `e2e` | 도구 설정, 규칙 검증, 브라우저 테스트                         |

서버 데이터는 TanStack Query, 전역 화면 설정은 Zustand가 관리합니다. 상품 등록 같은
지역적인 폼 입력은 해당 화면의 React 상태로 유지합니다.

## 반영한 개선

### 상품 등록 검증과 표시 분리

[product-form.ts](../src/features/create-product/model/product-form.ts)에 입력 타입, 초기값,
길이 제한, 검증 규칙을 모았습니다. 훅은 입력과 오류 상태를 관리하고, UI는 오류 식별자를
현재 언어로 번역합니다. 오류가 이미 표시된 상태에서 언어를 바꿔도 문구가 즉시 갱신됩니다.

제목 검증은 SEED 입력란과 같은 `unicode-segmenter`를 사용합니다. 이모지·조합형 한글을
포함한 40자 제목을 등록할 수 있고, 41자는 오류로 안내합니다. 제한값은 글자 수 표시와
한국어·영어 오류 문구가 함께 참조합니다. 추가한 직접 의존성은 SEED가 이미 사용하던
`unicode-segmenter@0.17.3`이며 기존 의존성 버전은 변경하지 않았습니다.

### 상품 조회 요청의 취소 책임 정리

기존에는 라우터의 취소 신호가 쿼리의 취소 신호를 덮어써서, 쿼리를 취소해도 실제 통신은
중단되지 않았습니다. [상품 쿼리](../src/entities/product/model/queries.ts)가 TanStack Query의
신호를 통신 계층에 전달하도록 통일했습니다.

로더가 시작한 조회는 화면을 떠났다는 이유만으로 중단하지 않아, 돌아왔을 때 같은 요청과
캐시를 사용할 수 있습니다. 명시적인 쿼리 취소는 실제 요청도 중단합니다. 이는 쿼리가
제공하는 신호를 전송 계층에 전달하는 [TanStack Query의 취소 방식](https://tanstack.com/query/latest/docs/framework/react/guides/query-cancellation?from=reactQueryV3)을 적용한 것입니다.

라우트 테스트는 쿼리 구현을 대체하던 모형을 제거하고 `fetch` 응답만 대체하여, 실제
로더·쿼리·HTTP 저장소·오류 처리 경로를 함께 확인합니다.

### 상품 데이터 접근 코드 분리

[product-api.ts](../src/entities/product/api/product-api.ts)는 환경에 맞는 저장소 선택과
호출 진입점만 담당합니다. HTTP 저장소, 메모리 저장소, 저장소 인터페이스, 데모 데이터는
각 파일로 나눴고, 기존 저장소 테스트도 구현 옆으로 옮겼습니다. 외부 슬라이스는 계속
`@/entities/product`의 공개 API를 통해 접근합니다.

### 중복 규칙과 시작 안내 정리

로그인과 단계별 폼의 이메일 검사 규칙을 [공통 유틸리티](../src/shared/lib/validation.ts)로
모았습니다. 상품 카테고리 선택은 타입 단언 대신 실제 허용 목록으로 확인합니다.
README의 pnpm 설치 버전을 `package.json`에 지정된 11.23.0으로 맞췄습니다.

## 검증 결과

- `pnpm verify` 통과: 29개 테스트 파일, 106개 테스트. 타입, ESLint, FSD, 서식, SEED 토큰,
  브랜드, 스니펫 호환성, 한국어·영어 번역, 프로덕션 빌드 검사도 통과했습니다.
- `pnpm test:e2e` 통과: 브라우저 테스트 8개 통과, 12개는 기존 설정에 따라 생략했습니다.
  320·480·768·1280·1440px 화면, 로그인 유지, 상품 등록 후 상세 이동, 화면 크기 변경 시
  계정 메뉴 동작을 확인했습니다. 핵심 흐름은 지정된 화면 크기에서 한 번씩 실행합니다.

## 제품화할 때 이어갈 작업

- 세션 API는 현재 데모입니다. 서버 세션 검증과 상품 API 인증·권한 정책을 연결해야 합니다.
- 소셜 로그인과 채팅 버튼은 화면 예시이며 실제 동작이 연결되어 있지 않습니다. 해당 서비스의
  인증 방식과 API가 정해지면 기능 슬라이스로 구현할 수 있습니다.
- 대시보드·프로필·단계별 폼은 예시 데이터와 동작을 사용합니다. 실제 데이터 계약이 정해지면
  관련 엔티티와 쿼리를 연결하는 작업이 필요합니다.
